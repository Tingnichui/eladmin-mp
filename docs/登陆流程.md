# 登陆流程

本文档用于在本地开发环境中验证 ELADMIN 管理端登陆链路。

## 1. 启动前提

登陆前先确认前后端服务已启动：

- 前端地址：`http://127.0.0.1:8013/`
- 后端验证码接口：`http://127.0.0.1:11280/auth/code`
- 前端代理验证码接口：`http://127.0.0.1:8013/auth/code`

可用以下命令快速检查：

```powershell
Invoke-WebRequest http://127.0.0.1:8013 -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:11280/auth/code -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8013/auth/code -UseBasicParsing
```

如任一接口无法访问，先参考 [项目启动流程](./项目启动流程.md) 处理前后端启动问题。

## 2. 账号密码确认

不要把真实账号、密码、验证码、令牌或其他凭据写入文档、代码、提交信息或日志说明。

每次需要登陆系统时，应现场向用户确认：

- 登陆账号
- 登陆密码
- 是否需要填写指定验证码

如果用户说明当前测试环境不校验验证码，可在验证码输入框中填写任意非空内容，例如 `1234`。

## 3. 浏览器登陆步骤

1. 打开前端地址：

   ```text
   http://127.0.0.1:8013/
   ```

2. 确认页面显示 `ELADMIN 后台管理系统` 登陆表单。
3. 向用户确认账号、密码和验证码要求。
4. 输入账号。
5. 输入密码。
6. 输入验证码。
7. 点击 `登 录`。
8. 等待页面跳转到首页。

登陆成功后通常会进入：

```text
http://127.0.0.1:8013/dashboard
```

页面标题通常为：

```text
首页 - ELADMIN
```

## 4. 登陆后检查

登陆成功后建议确认以下内容：

- 地址栏为 `/dashboard`。
- 页面左侧能看到系统菜单，例如 `首页`、`系统工具`、`系统管理` 等。
- 首页统计卡片或主要内容区域正常显示。

如果仍停留在登陆页，先检查页面提示、浏览器控制台和后端日志。

## 5. 浏览器保存密码与记住我

- 浏览器密码管理器可以保存并自动填充用户输入的原始密码。
- 前端只在调用登陆接口时临时对密码副本进行 RSA 加密，不得把密文回填到密码输入框。
- 应用不得在 Cookie、Local Storage 或 Session Storage 中保存明文密码或加密后的密码。
- “记住我”只控制登陆令牌的 Cookie 有效期，可以同时记住用户名，不负责保存密码。
- 页面加载时会清理旧版本遗留的 `password` Cookie。
- 如果浏览器仍填充旧版本保存的加密密码，页面会要求重新输入原密码；登陆成功后应在浏览器提示中更新保存的密码。

## 6. 常见问题

### 前端页面打不开

先确认 `8013` 端口是否监听：

```powershell
Get-NetTCPConnection -ErrorAction SilentlyContinue |
  Where-Object { $_.LocalPort -eq 8013 }
```

如未监听，参考 [项目启动流程](./项目启动流程.md) 启动前端。

### 验证码接口失败

如果 `http://127.0.0.1:8013/auth/code` 返回错误，通常是后端未启动、后端启动失败或前端代理无法连接后端。

先检查后端：

```powershell
Invoke-WebRequest http://127.0.0.1:11280/auth/code -UseBasicParsing
```

如后端不可访问，查看 `runtime-logs/backend.out.log` 和 `runtime-logs/backend.err.log`。

### 测试环境验证码

如果测试环境已配置为不校验验证码，验证码输入框仍建议填写任意非空值，避免前端表单校验拦截提交。

如果环境开启了验证码校验，需要按页面验证码图片填写真实验证码。
