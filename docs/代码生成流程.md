# 代码生成流程

本文档用于通过“系统工具 -> 代码生成”稳定生成前后端基础 CRUD。代码生成阶段只负责基础能力；复杂撮合、统计和页面交互必须等 CRUD 验收通过后再做。

## 1. 完成标准

只有同时满足以下条件，才算代码生成完成：

- 目标表及代码生成器元数据表存在。
- 字段配置和生成配置已经分别保存。
- 前后端文件真实生成到正确模块，并且均为 UTF-8。
- 后端模块编译通过，运行中的后端已加载新代码。
- 用户要求创建菜单时，页面菜单位于正确父菜单下，`list/add/edit/del` 权限前后端一致。
- 用户要求完整 CRUD 验收时，列表、分页、查询、新增、修改、删除和导出完成验证。
- 用户明确要求“只生成代码、暂不创建菜单”时，允许跳过菜单、角色授权和页面 CRUD 操作，但必须完成生成文件检查、后端编译、前端 lint 和生产构建。

页面提示“保存成功”或“生成成功”不代表以上步骤已经全部完成。

## 2. 固定执行顺序

严格按以下顺序执行：

```text
环境检查
  -> 表结构与数据性质确认
  -> 生成器元数据表检查
  -> 字段同步与配置
  -> 保存生成配置
  -> 保存字段并生成
  -> 文件落盘检查
  -> 编译并重启后端
  -> 按任务范围决定是否配置菜单与权限
  -> 按任务范围完成代码验证或完整 CRUD 验证
  -> 业务定制
```

不要在基础 CRUD 尚未跑通时同步加入撮合、统计或复杂表单逻辑。

## 3. 环境检查

开始前完成以下检查：

1. 阅读 `docs/README.md`、`docs/项目启动流程.md` 和 `docs/登陆流程.md`。
2. 确认 `AGENTS.md` 指定的 Maven、settings、本地仓库和 Java 8 路径存在。
3. 执行 `git status --short`，记录并保留用户已有修改。
4. 确认前端、后端和验证码接口可访问。
5. 按登录流程现场确认账号、密码和验证码要求。
6. 进入“系统工具 -> 代码生成”，确认目标表来自当前后端实际连接的数据库。

启动后端前必须确认当前环境的 `JASYPT_ENCRYPTOR_PASSWORD`，不得把密钥、数据库密码或登录凭据写入文档、代码和提交信息。

## 4. 表结构与数据性质确认

建表 SQL 应保存到 `sql/`，并使用 UTF-8。生成前核对：

- 主键、类型和自增策略。
- 字段类型、长度、默认值、是否允许为空及字段注释。
- `datetime/timestamp` 是否由数据库自动维护。
- 是否存在 `bigint` 标识字段；它可能超过 JavaScript 最大安全整数。
- 字符串日期、长文本、字典、枚举和金额数量字段的实际类型。
- 是否存在重复字段注释，避免表单标签和导出表头重名。
- 表中是否已有真实业务数据。

空表或明确的测试表可以做完整 CRUD 验证；已有真实数据的表默认只做只读验证，除非用户明确授权写入测试数据。

## 5. 生成器元数据表检查

代码生成器依赖：

- `code_column`：保存字段展示、表单、查询和字典配置。
- `code_config`：保存模块、包名和生成路径配置。

首次使用或数据库环境切换后，先确认这两张表存在。缺失时执行：

```text
sql/code_generator_metadata.sql
```

该脚本使用 `CREATE TABLE IF NOT EXISTS`，不会删除已有配置。

典型错误：

```text
Table 'eladmin.code_column' doesn't exist
```

出现此错误时先补元数据表并刷新代码生成页面，不要反复点击“同步”。

## 6. 字段配置规则

进入目标表的“配置”页面后，先同步字段，再逐行检查。

- 主键：不必填、不在列表显示、不在表单显示、不配置查询。
- `bigint` 编号：按标识符处理，前端避免转为可能丢失精度的 JavaScript Number。
- `int/decimal/float/double` 业务数值：使用数字框。
- `date/datetime/timestamp`：使用日期控件；需要范围查询时选择 `BetWeen`。
- `create_by/update_by/create_time/update_time`：由框架维护，不进入新增和编辑表单。
- 数据库默认生成或 `on update CURRENT_TIMESTAMP` 的时间字段：不强制用户填写。
- 名称、编码和交易对：根据使用场景选择 `Like` 或 `=`。
- 状态和类型：先维护字典，再使用下拉框并绑定准确的字典编码。
- 长文本：使用文本域。

保存前再次确认主键隐藏、必填校验、日期格式、查询方式和字典绑定。

## 7. 生成配置

投资模块的标准配置：

```text
模块名称：eladmin-invest
项目包名：me.zhengjie.invest
前端路径：C:\project\eladmin-mp\eladmin-web\src\views\invest\<页面目录>
作者名称：按项目现有习惯填写
是否覆盖：默认否
```

前端路径必须是当前工作区 `eladmin-web/src/views` 下的绝对路径。生成器会自动推导 `eladmin-web/src/api`，并拒绝写入工作区外的路径。

表前缀只在确实需要从类名中移除时填写。例如：

```text
表名：binance_spot_core_position
不去前缀：BinanceSpotCorePosition / binanceSpotCorePosition
去前缀 binance_spot_：CorePosition / corePosition
```

同一表重复保存配置时，应复用最新 `config_id` 并清理历史重复配置，避免生成时报 `TooManyResultsException`。

## 8. 保存和生成顺序

字段配置和底部生成配置是两套独立数据，必须按以下顺序操作：

1. 完成字段配置。
2. 填写底部生成配置。
3. 点击底部“保存”。
4. 重新读取配置，确认模块、包名、路径、接口名称和覆盖策略正确。
5. 点击顶部“保存&生成”。
6. 立即检查文件系统和 `git status --short`。

接口方式与页面方式等价：

1. `GET /api/generator/tables?name=<table>&page=1&size=10`
2. `GET /api/generator/columns?tableName=<table>`
3. `PUT /api/generator` 保存完整 `ColumnInfo` 数组
4. `PUT /api/genConfig` 保存 `GenConfig`
5. `GET /api/genConfig/<table>` 复查配置
6. `POST /api/generator/<table>/0` 生成文件

通过接口保存字段时，应构造完整对象，不要只回传局部字段：

```text
id、tableName、columnName、columnType、keyType、extra、remark、
notNull、listShow、formShow、formType、queryType、dictName
```

## 9. 生成路径和文件检查

生成器会从运行目录向上查找包含目标模块 `pom.xml` 的后端根目录；找不到时，再根据 `eladmin-web` 的位置反推同级 `eladmin`。找不到真实模块时直接报错，不应静默生成嵌套模块。

以 `binance_spot_core_position` 为例，标准文件应为：

```text
eladmin/eladmin-invest/src/main/java/me/zhengjie/invest/domain/BinanceSpotCorePosition.java
eladmin/eladmin-invest/src/main/java/me/zhengjie/invest/domain/dto/BinanceSpotCorePositionQueryCriteria.java
eladmin/eladmin-invest/src/main/java/me/zhengjie/invest/mapper/BinanceSpotCorePositionMapper.java
eladmin/eladmin-invest/src/main/resources/mapper/BinanceSpotCorePositionMapper.xml
eladmin/eladmin-invest/src/main/java/me/zhengjie/invest/service/BinanceSpotCorePositionService.java
eladmin/eladmin-invest/src/main/java/me/zhengjie/invest/service/impl/BinanceSpotCorePositionServiceImpl.java
eladmin/eladmin-invest/src/main/java/me/zhengjie/invest/rest/BinanceSpotCorePositionController.java
eladmin-web/src/api/binanceSpotCorePosition.js
eladmin-web/src/views/invest/binanceSpotCorePosition/index.vue
```

重点检查：

- 后端没有生成到 `eladmin-system/eladmin-invest` 或仓库根目录下的错误模块。
- 前端 API 和页面目录正确。
- 中文注释、日志和页面文案是严格 UTF-8。
- 没有覆盖无关文件。
- `bigint` 输出和查询不会因前端数字精度丢失。

## 10. 构建和重启

修改生成器本身后，先运行生成器测试并安装最新模块：

```powershell
cd eladmin
& 'C:\MyProgram\develop\Maven\apache-maven-3.5.4\bin\mvn.cmd' `
  -s 'C:\MyProgram\develop\Maven\apache-maven-3.5.4\conf\settings.xml' `
  -Dmaven.repo.local='C:\MyProgram\develop\Maven\apache-maven-3.5.4\repo' `
  -pl eladmin-generator -am -DskipTests=false clean install
```

业务代码生成后，至少编译 `eladmin-invest` 及其依赖。运行中的后端必须重启后才会注册新 Controller。重启前必须按项目规定确认 `JASYPT_ENCRYPTOR_PASSWORD`。

如果生成文件仍体现旧模板行为，说明当前后端加载的仍是旧版 `eladmin-generator` jar，应先停止旧进程、重新安装模块并重启，再重新生成。

## 11. 菜单与权限

本步骤取决于任务范围。用户明确要求暂不创建菜单时：

- 不写入 `sys_menu` 和 `sys_roles_menus`。
- 不为了验证生成代码临时创建菜单。
- 不把动态路由无法访问视为代码生成失败。
- 在交付说明中明确记录“菜单与角色权限未创建”。

需要创建菜单时，按以下规则执行。

创建页面菜单并挂到“投资管理”下：

```text
菜单标题：<中文功能名>
组件路径：invest/<页面目录>/index
菜单 path：<页面目录>
权限：<permissionPrefix>:list
```

页面菜单下创建按钮权限：

```text
<permissionPrefix>:add
<permissionPrefix>:edit
<permissionPrefix>:del
```

之后给目标角色追加父菜单、页面菜单和按钮权限，重新登录或刷新动态路由。权限前缀必须与 Controller 和前端 `v-permission` 完全一致。

菜单、按钮权限和角色授权应另存为可重复执行的 SQL，避免只存在于单个开发数据库。

## 12. CRUD 验证

先区分两种验收范围：

### 12.1 仅生成代码

用户要求“生成之后代码没有问题即可”或明确暂不创建菜单时，至少完成：

1. 后端实体、DTO、Mapper、Service、Controller 文件齐全。
2. 前端 API 和 Vue 页面文件齐全。
3. 后端目标业务模块测试或编译通过。
4. 生成器自身有修改时，生成器测试通过。
5. 新增前端 JS/Vue 文件通过 ESLint。
6. 前端生产构建成功。
7. `git diff --check` 无空白错误，且未生成到错误目录。

此范围不要求创建菜单、角色授权，也不对真实业务表执行新增、修改或删除。

### 12.2 完整 CRUD 验收

按以下顺序验证：

1. 菜单和页面可访问，标题及面包屑正确。
2. 列表接口返回成功。
3. 分页和排序正确。
4. 查询条件生效。
5. 新增后能重新查询到记录。
6. 修改后数据库和页面回显一致。
7. 删除目标测试记录成功。
8. 导出文件可打开，字段与列表一致。
9. 无权限角色无法看到或调用对应操作。

测试数据必须容易识别，只删除本轮新建的记录。真实业务表未经授权不执行写入和删除验证。

## 13. 常见问题

### `code_column` 不存在

执行 `sql/code_generator_metadata.sql` 后刷新页面，再次进入配置。

### 点击“保存&生成”提示“请先配置生成器”

先保存底部生成配置，再重新读取确认 `config_id` 已生成，最后执行“保存&生成”。

### 同一表出现多条生成配置

使用新版生成器重新保存一次。新版保存逻辑会复用最新配置并清理历史重复项，不要删除整张 `code_config`。

### 文件生成到错误目录

确认模块名为 `eladmin-invest`，前端路径位于当前工作区。升级并重启生成器后重新生成；不要把错误目录长期保留。

### 中文乱码

确认运行中的后端已加载使用 UTF-8 Writer 的新版生成器。不要把已经错误解码的乱码文本直接另存为 UTF-8。

### 菜单访问 404

检查后端是否重启、组件路径、菜单 path、父菜单、角色授权以及 `/api/menus/build` 返回的动态路由。

## 14. 基础 CRUD 与业务定制边界

代码生成阶段处理：表结构映射、基础 Controller/Service/Mapper、前端列表表单、权限、菜单、编译和 CRUD 验证。

以下内容放到 CRUD 验收之后：撮合规则、底仓排除逻辑、统计口径、批量操作、复杂表单、业务校验和专项性能优化。
