# 代码生成流程

本文档以 `invest_trade_analysis` 为例，记录本项目使用系统工具生成前后端 CRUD 代码的推荐流程。后续新增其他表时，优先按本文档执行。

## 1. 基本原则

- 新增标准 CRUD 功能时，优先使用系统工具 -> 代码生成。
- 先生成基础前后端代码，确认增删改查正常，再做业务页面和逻辑微调。
- 不要一开始就手写整套 Controller、Service、Mapper、前端 API 和页面。
- 如果生成结果有中文乱码或字段配置错误，优先修正生成配置后重新覆盖生成。
- 生成后的业务定制代码要控制范围，避免破坏 eladmin 原有 CRUD 机制。

## 2. 生成前准备

1. 确认数据库表已经创建。
2. 确认表名、字段名、字段注释清晰。
3. 确认哪些字段需要：
   - 列表展示
   - 表单录入
   - 查询筛选
   - 必填校验
   - 字典项
   - 日期范围查询
4. 先维护需要用到的字典项。
5. 确认菜单名称、模块名称、权限标识。

以 `invest_trade_analysis` 为例：

- 表名：`invest_trade_analysis`
- 菜单名称：交易分析
- 后端模块：`eladmin-invest`
- 前端目录：`src/views/invest/investTradeAnalysis`
- 接口路径：`api/investTradeAnalysis`
- 权限标识：`investTradeAnalysis:list/add/edit/del`

## 3. 字典项配置

生成代码前，先到系统管理 -> 字典管理维护业务字典。生成器配置字段时，再把对应字段绑定到字典。

`invest_trade_analysis` 使用的字典：

- `invest_trade_analysis_direction`：交易方向。
  - 示例值：看涨、看跌。
  - 对应字段：`direction`。
- `invest_trade_analysis_entry_type`：入场类型。
  - 示例值根据实际交易策略维护。
  - 对应字段：`entry_type`。
- `invest_trade_quality_level`：交易质量。
  - 示例值：低质量、中等质量、高质量，或按实际复盘规则维护。
  - 对应字段：`quality_level`。

生成器字段配置建议：

- 字典字段的表单类型使用下拉选择。
- 查询类型使用等值查询，入场类型如果需要模糊搜索再单独调整。
- 前端生成后检查页面 `dicts` 是否包含对应字典编码。
- 表格展示时应显示字典 label，不直接显示 value。
- 新增或修改字典 value 后，要确认后端保存值和前端回显值类型一致，尤其是数字字典。

## 4. 表字段示例

`invest_trade_analysis` 当前主要字段：

- `direction`：交易方向，字典项，必填。
- `amount`：交易金额。
- `entry_type`：入场类型，字典项。
- `open_time`：开仓时间，可做时间范围查询。
- `close_time`：平仓时间，可做时间范围查询。
- `open_price`：开仓价格。
- `close_price`：平仓价格。
- `net_profit`：盈亏金额。
- `open_reason`：开仓原因。
- `open_kline_images`：开仓 K 线图片 JSON。
- `close_kline_images`：平仓 K 线图片 JSON。
- `score`：开仓评分。
- `review_conclusion`：平仓复盘。
- `quality_level`：交易质量，字典项。
- `remark`：交易备注。

明确不要放入该表的字段：

- 交易编号。
- 交易标的。
- 奖金支付率。
- 复盘状态。

## 5. 生成器操作流程

1. 登录后台系统。
2. 进入系统工具 -> 代码生成。
3. 导入或同步目标表。
4. 找到目标表，例如 `invest_trade_analysis`。
5. 进入生成配置。
6. 配置基础信息：
   - 模块名称：`invest`
   - 功能名称：交易分析
   - 实体类名：`InvestTradeAnalysis`
   - 作者：按当前项目习惯填写
   - 生成方式：覆盖已有代码时需要确认目标文件可被覆盖
7. 配置字段信息：
   - 字段描述使用中文业务名称。
   - 交易方向、入场类型、交易质量配置为字典项。
   - 字典编码分别选择 `invest_trade_analysis_direction`、`invest_trade_analysis_entry_type`、`invest_trade_quality_level`。
   - 开仓时间、平仓时间配置为时间字段。
   - 大文本字段使用 textarea。
   - 金额、价格、评分字段按数字类型处理。
8. 生成前后端代码。
9. 如果生成到压缩包，解压后把文件放到对应模块；如果直接生成到项目目录，检查目标路径是否正确。
10. 重启或刷新前后端，验证基础页面。

## 7. 生成后检查清单

基础功能：

- 列表查询正常。
- 新增正常。
- 修改正常。
- 删除正常。
- 导出正常。
- 分页正常。

权限和菜单：

- 菜单能正常展示。
- `list/add/edit/del` 权限标识和前后端一致。
- 非管理员用户权限按角色配置生效。

字段和筛选：

- 表格列名称和表单 label 一致。
- 筛选项选择后能主动查询。
- 时间字段使用时间范围选择。
- 字典字段显示中文 label，不直接显示 value。
- 必填校验符合业务要求。

编码：

- 所有生成文件使用 UTF-8。
- 中文菜单、字段注释、页面文案不能乱码。

## 8. `invest_trade_analysis` 的后续定制

`invest_trade_analysis` 生成基础代码后，又做了以下业务定制：

- 列表筛选项调整为交易方向、入场类型、交易质量、开仓时间、平仓时间。
- 表单拆成独立组件 `InvestTradeAnalysisForm.vue`。
- 表单分为订单识别、基础信息、开仓记录、平仓记录、复盘。
- K 线图片按 `1D、4H、2H、1H、15M、5M` 管理。
- 开仓和平仓 K 线图片以 JSON 字符串保存到主表字段。
- 增加订单截图 OCR 识别接口 `POST /api/investTradeAnalysis/ocr`。
- OCR 业务解析放在 Service，不放 Controller。
- 前端只消费 OCR 识别后的业务字段，不解析 OCR 原始文本。
- 增加复制 JSON、图片预览切换、粘贴上传等交互。

这些属于业务定制，不是代码生成器默认能力。后续其他表如果也有复杂交互，应先生成基础代码，再单独拆组件和补业务逻辑。

## 9. 常见问题

### 中文乱码

优先检查数据库连接、生成器配置、文件编码是否为 UTF-8。确认后使用代码生成器覆盖重新生成，不建议直接在乱码文件上逐个手修。

### 生成路径不对

检查模块名、包路径、前端路径配置。后端业务模块应放到对应 `eladmin-*` 模块中，前端页面应放到 `eladmin-web/src/views` 下。

### 字典字段显示 value

检查：

- 系统管理 -> 字典管理中是否已有对应字典。
- 前端页面 `dicts` 是否引入该字典。
- 表格列和下拉框是否使用字典 label 显示。

### 修改字段后页面异常

字段变更后需要同步：

- 数据库表。
- Entity。
- Mapper XML。
- QueryCriteria。
- Controller / Service 导出逻辑。
- 前端 API。
- 前端 `defaultForm`。
- 列表列、筛选项、表单字段。
