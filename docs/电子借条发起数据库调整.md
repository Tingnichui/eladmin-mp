# 电子借条发起数据库调整

## 已确定的结构

保留 `iou_user` 和 `iou_note`，只新增 `iou_note_plan`。不新增邀请、签署或条款版本表，不新增双方用户ID，继续通过身份证HMAC关联用户。

开放链接流程为：填写借款条件和计划→发起人签署→分享链接→另一位已核验用户主动接受并签署→后端补齐对方身份。对方不得修改条件，不增加发起人二次确认。登录、实名核验、禁止本人签另一方、借条有效状态及并发唯一绑定仍须由后端校验；这些写入接口本轮尚未实现。

## SQL 文件与执行顺序

- 新数据库：先执行原账号/注册初始化，再执行 `sql/iou_note.sql`、`sql/iou_note_plan.sql`、`sql/iou_dict.sql`。
- 已有电子借条表：执行 `sql/iou_note_initiation_migration.sql`。它包含身份字段放宽、利率精度、24个扩展字段、计划表及状态字典，支持重复执行。
- 生成器重新同步字段后，按 `sql/iou_generator_fields.sql` 隐藏内部签署快照、凭证、文件标识和并发版本。不要重新生成覆盖现有敏感字段保护代码。

升级脚本不删除记录，不修改已有状态编号，不为旧记录伪造发起人角色、还款计划、签署时间或签署凭证。旧记录新增字段为空或默认未发起状态，不等于新签署流程成功。

## 主表调整

双方姓名、身份证HMAC和身份证密文这六个字段允许NULL，对方未知时必须使用NULL，不能写“待邀请”等占位身份。

年利率调整为 `decimal(12,8)`，数据库存比例值，例如6%存0.06，不把页面百分数直接入库。

| 字段 | 用途 |
| --- | --- |
| creator_role | 1借款人、2出借人，旧记录可为空。 |
| repayment_method | once、annuity、principal、interest、flat、custom。 |
| installment_count / repayment_cycle_months / first_due_date | 期数、周期月数及首期日期，自定义周期可为空。 |
| interest_rule / calculation_version | 计息规则及后端计算版本。 |
| prepayment_rule / overdue_terms | 提前还款规则及逾期约定。 |
| terms_snapshot / terms_hash / terms_locked_at | 不可覆盖的签署条款和计划快照、SHA256及锁定时间。 |
| borrower_sign_status / lender_sign_status | 0未发起、1处理中、2成功、3失败。 |
| 双方 sign_request_id / sign_evidence_id / sign_file / sign_file_hash | 各自请求、凭证、签署文件和SHA256，失败重试与重复回调由专用服务维护。 |
| agreement_hash | 最终协议SHA256，原agreement_file继续作为最终文件标识。 |
| row_version | 并发版本号，后续绑定必须用带状态/空身份条件的原子更新推进。 |

现有双方签署时间继续保留。发起人的原签署文件与对方签署后的最终文件分开保存，不能补齐身份后覆盖原签署内容。内部快照、摘要、锁定时间、签署状态、凭证及版本号不接受普通表单赋值，也不出现在普通序列化、审计参数或toString中。

## 计划表

`iou_note_plan` 保存 id、note_id、period_no、due_date、principal_amount、interest_amount、total_amount、remaining_principal、create_time。金额均为decimal(18,2)，(note_id,period_no)唯一，note_id引用iou_note.id并限制直接删除父记录。

一次性还款保存一期。remaining_principal是按约定计划还完本期后的余额，不能当作实际待还余额。实际还款流水、冲抵、提前结清与展期不在本轮实现范围。

后续写入服务须验证日期递增、金额非负、本金合计等于主表本金、本息合计和尾差，保存主表、计划与快照时使用事务；发起签署开始后禁止修改计划。当前没有计划CRUD或用户端创建接口。

## 状态与后端兼容

保留0至6编号，追加7“待对方签署”。H5列表、详情和更多状态筛选已识别状态7。已绑定的旧“待确认”查询保持原规则，未知对方不会成为任意用户“待我确认”的记录。

后台支持显式creator_role的未签署草稿：本人身份从指定发起人的已核验资料读取，对方必须全空；半套身份被拒绝。历史双方齐全的后台录入仍保留。后台不能伪造状态7或签署成功时间。

后台更新和删除先在事务中锁定记录，拒绝已经锁定、正在签署、签署成功或状态7的记录；未签署更新推进row_version。还款计划的外键也会阻止直接删除带明细的父记录。H5真实创建、签署、链接接受、条款快照生成及并发绑定尚未接入，不能将数据库字段存在解释为功能已开放。
