# 安据存注册开放

2026-10-13 更新注册协议版本为 2026-10-13-v1，运营名称按用户提供的“安据存”，联系邮箱 anjucun_admin@163.com，域名 ajc.tingnichui.com。

## 当前流程

按用户要求，注册、IOU 登录、公共验证码校验不设置新增的频率限制；同一身份证的五分钟核验等待锁也已取消。核验失败后用户可以重新完成验证码并立即提交，可能产生新的核验费用；服务仍不自动重试收费调用。旧 Redis 等待锁及计数即使尚未到期，也不再读取或影响请求。验证码单次消费、身份查重、唯一约束及事务保留。

验证码弹窗仅负责公共安全验证，不展示注册、登录或实名核验业务说明。调用 /api/security/captcha/verify 在弹窗内处理错误，失败保留弹窗并刷新图片；成功后返回两分钟有效、Redis 原子单次消费的凭证，随后由注册接口消费；IOU 登录不再要求验证码。通过凭证不能用于再次签发凭证或续期，业务请求不依赖前端“已通过”布尔值。

注册接口失败（如身份核验未通过）和协议加载异常使用居中的“注册提示”弹窗及“知道了”按钮，不再显示在注册按钮下方。输入字段校验仍在对应字段旁展示。

注册提交成功后，H5 复用原 /auth/login 接口及账号密码校验完成无验证码自动登录，复用现有令牌存储和鉴权，然后跳转主页 /。注册接口保留 loginCaptcha 字段兼容旧客户端，新客户端不再依赖它。不再次弹出验证码，不保存身份证或密码到浏览器存储。自动登录故障不视为注册失败：弹窗明确提示账号已创建，关闭后到登录页，并阻止重复注册；注册成功后签发凭证失败仍返回201、loginCaptcha=null，不能误报账号创建失败。

注册页从匿名接口 `/api/iou/auth/policies` 加载用户协议、隐私政策和实名核验授权正文，使用纯文本弹窗展示，不再展示占位协议或验证码体验流程。

用户分别主动勾选协议确认和实名核验授权，再完成图形验证码。后端要求二者均为 true、协议版本一致、身份证出生日期有效且年满18周岁。缺失授权、未成年、错误验证码和重复身份不会发起云账户付费核验。

核验通过后，事务内复用 UserService.create 创建 sys_user，关联 iou_user。密码仅存于 sys_user；固定部门、岗位和角色 ID 均为 920001，角色仅拥有 iou:profile:read。身份证加密存储，HMAC 查重。用户协议、隐私政策和独立授权共用同一版本，只有全部确认才保存 agreement_version、agreement_accepted_at，因此该记录表示对该版本三份文件的完整确认，不是仅确认用户协议。

## 用户名与昵称

新注册的系统用户名固定为 `iou_` 加完整64位身份证 HMAC-SHA256，即 `id_no_hash`，共68位。同一身份证在同一查重密钥下生成同一个用户名，不再使用随机 UUID。
昵称使用核验通过的真实姓名并去除首尾空白；不同用户可以同名。注册前和事务内检查身份证查重值及用户名，重复注册提示直接登录，不覆盖既有密码、昵称或账号状态。数据库的身份证及用户名唯一索引继续兜底并发写入。

已有账号通过 `sql/iou_deterministic_username_migration.sql` 迁移，保留系统用户ID、密码、启停、岗位、角色和借条关联。执行前核对身份证查重值与当前项目密钥一致，存在无效身份或目标用户名冲突时应停止。执行后清理变更账号旧、新用户名的登录缓存及在线会话，以及用户ID相关缓存，用户重新登录。迁移脚本可重复执行。
管理端允许借条账号68位用户名和1至64字昵称，普通后台账号仍沿用原有长度规则。身份证登录通过身份关联查找系统账号，迁移不改变身份证登录方式。

## 正文与配置

身份证查重密钥使用 application.yml 的 iou.identity.hmac-key，以 Jasypt ENC 密文保存，不再依赖单独设置 IOU_IDENTITY_HMAC_KEY。解密仍使用现有 JASYPT_ENCRYPTOR_PASSWORD。首次配置时已检查 iou_user 为空；已有账号后禁止随意更换查重密钥，否则会影响身份证登录匹配和重复注册校验。迁移部署时必须保留相同密钥。

正文位于 eladmin-system/src/main/resources/iou-policies/ 下的 agreement.txt、privacy.txt、identity.txt。修改正文必须同步更新 iou.registration.agreement-version 并保留历史版本。旧版三份正文已归档至 iou-policies/history/2026-10-10-v1/。部署时直接维护 application.yml 中对应的版本和协议链接。

application.yml 直接配置协议版本与以下 HTTPS 链接：

- https://ajc.tingnichui.com/api/iou/auth/policies/agreement
- https://ajc.tingnichui.com/api/iou/auth/policies/privacy
- https://ajc.tingnichui.com/api/iou/auth/policies/identity

公网部署须启用 HTTPS 并把 /api 转发至后端，以上地址才可在公网访问。当前本地页面通过同源开发代理读取同一正文，不依赖公网域名可用。

## 上线边界

打开本地注册不代表公网部署完成，也不构成法律合规保证。运营方仍需核对“安据存”是否为完整法律主体名称、云账户实际签约主体和数据处理关系，以及实际存储地点、保留周期、注销删除流程。当前沿用框架原有旧 RSA 登录密钥，公网上线前应升级密钥并启用 HTTPS。

已连接真实云账户接口，实际提交符合条件的注册将触发收费核验；不得使用未经授权的身份信息进行验证，不自动重试付费请求。
