# 字典维护规范

本文用于约束系统字典的命名、取值、展示、缓存和代码生成配置，避免同义不同名、value 混用、历史数据无法翻译、导出字段不一致等问题。

## 1. 字典命名

字典名使用“小写下划线”，优先按以下格式命名：

```text
业务模块_业务对象_字段名
```

示例：

```text
gym_member_status
gym_contract_status
gym_contract_type
invest_trade_status
media_crawler_platform
```

只有真正跨模块通用的字典，才允许使用短名称：

```text
yes_no
enable_disable
gender
```

禁止随意使用过于宽泛的名称：

```text
status
type
state
record_status
```

## 2. 字典 value

`value` 是业务数据中长期保存的稳定值，一旦上线并被业务数据引用，不允许随意修改含义。

同一个字典内必须保持 value 类型一致：

- 字符串字段推荐使用稳定英文码：`active`、`inactive`、`expired`、`cancelled`。
- 数字字段保持数字码：`0`、`1`、`10`、`20`。
- 禁止在同一个字典里混用数字码和英文码。

如果已有业务数据引用了某个 value，后续只能新增新 value，不能直接改旧 value 的含义。

## 3. 字典 label

`label` 是展示文案，可以根据业务语言调整，但修改前必须确认影响范围。

示例：

```text
value: active
label: 正常
```

如果 label 从“正常”改为“有效”，历史数据仍通过 `active` 找到新展示文案。

## 4. 字典项删除与停用

线上已被业务数据引用过的字典项禁止硬删除。

推荐处理方式：

- 不再用于新数据：停用该字典项。
- 前端下拉：不展示停用项。
- 列表、详情、导出：仍允许根据历史 value 翻译旧 label。

如果硬删除字典项，历史数据可能在列表或导出中只显示 value，甚至显示为空。

## 5. 排序规则

每个字典项必须维护排序值。

建议：

- 常用项排前面。
- 状态类按业务流转顺序排序。
- 不依赖创建时间作为展示顺序。

示例：

```text
10 待生效
20 生效中
30 已到期
40 已作废
```

## 6. 备注与使用范围

字典或字典项备注中应记录使用范围，至少说明主要表和字段。

示例：

```text
用于 gym_contract_info.status
用于 gym_member_info.member_type
```

后续维护时，应先确认是否已有其他字段复用该字典，避免误改影响其他模块。

## 7. 一个字段只绑定一个字典

同一个业务字段在前端、后端、导出和代码生成配置中必须使用同一个字典名。

禁止出现：

- 页面使用 `gym_member_status`。
- 导出使用 `member_status`。
- 后端硬编码使用 `record_status`。

生成器字段配置了字典后，列表展示、表单控件和导出逻辑都应以该字典名为准。

## 8. 字典缓存

字典新增、修改、删除或停用后，必须刷新相关缓存。

当前导出模板通过 `RedisUtils#getDictLabel` 获取字典 label，维护时需要保证：

- 字典变更后缓存能被刷新。
- Redis 未命中时允许回退原始 value。
- 不能因为缓存缺失导致导出空值。

## 9. 字典与枚举边界

字典适合解决展示、筛选和导出翻译问题；不适合单独承载复杂业务状态机。

建议：

- 只用于展示和筛选：使用系统字典。
- 参与复杂业务判断：使用 Java enum，并让字典只负责 label 映射。
- 核心状态字段：优先明确枚举语义，再同步字典展示。

如果代码中已经大量判断某个状态值，应避免只在数据库字典中“散养”该状态。

## 10. 新增字典检查清单

新增字典或字典项前，至少检查：

- [ ] 字典名是否符合 `业务模块_业务对象_字段名`。
- [ ] 是否已有语义相同或相近的字典。
- [ ] value 类型是否和数据库字段一致。
- [ ] value 是否稳定，不会频繁改含义。
- [ ] label 是否符合当前页面和导出展示语言。
- [ ] 是否需要排序值。
- [ ] 是否写明使用范围。
- [ ] 已有业务数据是否会引用该 value。
- [ ] 停用是否比删除更合适。
- [ ] 前端、后端、导出和生成器配置是否使用同一个字典名。
- [ ] 是否需要 Java enum，而不是纯字典。

## 11. 代码生成注意事项

通过代码生成器配置字典字段时：

- 字典名必须使用已经确认的规范名称。
- Select、Radio 等控件必须绑定同一个字典。
- 导出字段如果是字典项，应导出 label，而不是原始 value。
- Redis 字典缓存未命中时，导出应回退原始 value。
- 如果字段参与业务判断，生成后应补充明确枚举或常量，不要在业务代码中散落魔法值。
