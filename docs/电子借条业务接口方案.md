# 电子借条业务接口方案

执行阶段调整（2026-10-11）：用户确认自建手写签署、本期免费。签署改为服务端同步事务提交，成功返回200；不接第三方供应商，不需要签署跳转、回调、异步候选人和后台供应商补偿。已实现接口、文件及数据库细节以[发起接口实现](./电子借条发起接口实现.md)为准。下文供应商章节保留为原方案，当前不适用。

设计日期：2026-10-11。本文是待开发方案；除标注“已有”的接口外，不表示已经实现或开放。范围覆盖现有发起页面、草稿、还款试算、双方签署、分享接受、查询和文件访问。实际还款流水、展期、催收和资金放款另行设计。

## 1. 已确定的业务流程

1. 用户登录并通过现有实名核验，选择自己是借款人或出借人。
2. 填写本金、日期、用途、备注、还款方式、利息及其他约定；对方信息为空。
3. 服务端试算，用户核对完整还款计划和条款预览。
4. 保存草稿，发起人签署。开始签署即冻结条款；签署成功进入“待对方签署”。
5. 发起人取得分享链接并发给对方。链接不指定接受人、不设置业务有效期、不限制转发。
6. 任一其他已实名用户打开链接，读取借条和本人拟加入信息。打开、预览均不绑定身份。
7. 对方确认原条款并签署，成功后由服务端补齐对方身份，生成双方最终文件，按收费配置决定生效状态。
8. 不增加发起人再次核对、再次确认的步骤。

不单独提供“接受邀请/绑定对方”写接口。不由客户端传入双方身份证、身份证HMAC或双方用户ID。当前登录系统用户ID先映射到iou_user，再使用现有实名资料和身份证HMAC判断当事人。

开放链接不等于任意用户可以查看所有借条列表。普通列表和详情仍只向发起人及已绑定当事人开放；持有链接的用户通过独立分享接口核对待签署借条。

## 2. 状态模型

### 2.1 主状态

| 值 | 名称 | 新流程用途 |
| --- | --- | --- |
| 0 | 草稿 | 包括未签署、发起人签署中、发起人签署失败；是否能编辑由签署阶段和锁定时间决定。 |
| 1 | 待对方确认 | 保留历史记录语义，新流程不产生。 |
| 2 | 已生效 | 双方签署成功、最终文件核验完成，并已满足服务费条件。 |
| 3 | 已结清 | 保留；本期不提供直接改为结清的接口。 |
| 4 | 已取消 | 草稿取消或发起人在对方尚未开始签署前撤销。 |
| 5 | 已拒绝 | 保留历史语义；任一分享链接访问者拒绝不能将整张借条改为已拒绝。 |
| 6 | 待支付服务费 | 仅在已经接入收费且双方签署及最终文件均完成时产生。 |
| 7 | 待对方签署 | 发起人已签，对方未签；包含对方签署中及最终文件生成中。 |

推荐流转：0→7→2；启用收费时0→7→6→2。0或7可以在满足撤销条件时转4。2/3不能使用发起撤销接口。

签署成功不是资金已经交付，也不是实际还款已经完成。系统不根据双方签署时间自动生成放款或还款记录。

### 2.2 签署子状态与展示阶段

双方sign_status沿用0未发起、1处理中、2成功、3失败。失败重试3→1；成功不允许再签。网络超时属于结果待查，不能直接当作失败。

DTO另返回stage和actions，不新增主状态编号：

| stage | 页面展示 | 可执行动作示例 |
| --- | --- | --- |
| DRAFT_EDITABLE | 待完成填写 | EDIT、DELETE、PREVIEW、SIGN_INITIATOR |
| INITIATOR_SIGNING | 发起人签署中 | VIEW、POLL_SIGNATURE |
| INITIATOR_SIGN_FAILED | 发起人签署失败，条款已锁定 | RETRY_SIGNATURE、CANCEL、COPY_TO_NEW |
| WAITING_COUNTERPARTY | 待对方签署 | SHARE、VIEW、CANCEL |
| COUNTERPARTY_SIGNING | 对方签署中 | VIEW、POLL_SIGNATURE |
| COUNTERPARTY_SIGN_FAILED | 对方签署失败 | SHARE、CANCEL；候选人可重试 |
| FINALIZING | 正在生成最终借条 | VIEW、POLL_SIGNATURE |
| WAITING_FEE | 待支付服务费 | VIEW；收费上线后PAY_FEE |
| EFFECTIVE / CANCELLED / SETTLED | 对应主状态 | VIEW；文件就绪时VIEW_AGREEMENT |

actions由服务端结合访问者角色、锁定时间、签署状态和配置计算，前端不能只判断status=0就展示编辑。

## 3. 通用接口约定

- 用户端前缀：`/api/iou/app`。复用现有登录鉴权和H5访问策略；不复用管理员`/api/iouNote`作为用户写接口。
- 金额用十进制字符串，单位元，两位小数；ID和version用字符串。利率字段annualRate为比例字符串，例6%传`"0.06000000"`；界面只负责百分数转换。
- 日期`YYYY-MM-DD`，业务时间以Asia/Shanghai返回带偏移量的ISO8601时间。已有不带时区的时间响应兼容过渡，不能静默按UTC解析。
- 业务表单使用专用DTO和字段白名单。身份、金额合计、签署结果、文件标识、主状态、锁定时间由服务端生成。
- 成功响应沿用现有直接JSON对象，列表沿用content/totalElements，不给已有接口强行新增data包裹。
- 创建、发起签署使用`Idempotency-Key`请求头。相同用户、接口、key、请求摘要返回同一业务结果；相同key不同内容返回409。随机UUID由前端在一次操作开始时生成，网络重试沿用。
- 编辑、删除、取消、签署提交携带version；签署还必须携带previewHash。版本冲突返回409并要求重新加载。
- previewHash是服务端预览内容的摘要，用于防止预览与签署不一致，不是鉴权令牌。签署时重算并比对，不能相信客户端提供的摘要。
- 未登录401；已登录但未实名或无操作权限403；不可见借条统一404；并发或状态冲突409；字段校验400；供应商暂不可用503。
- 新业务错误响应约定`{ status, code, message, fieldErrors?, timestamp }`，保留框架已有status/message字段。fieldErrors只含字段和提示，不含被拒绝的身份证等原值。
- 不记录身份证明文、密文、HMAC、完整合同正文、签署跳转URL或鉴权信息到普通访问/审计日志。审计记录业务ID、动作、操作者和结果。

## 5. 页面配置、表单和试算

### 5.1 GET /note-options

返回creationEnabled、signingEnabled、shareBaseUrl、calculationVersion、contractTemplateVersion、repaymentMethods、cycleMonths、minInstallments/maxInstallments、principalMin/principalMax、rateMax、maxTermDays、prepaymentRules、serviceFeePolicy。

每种方式说明requiredFields和disabledFields，便于前端切换时清理不适用字段。一期一次性、标准分期2至60期、周期1/3个月沿用页面设计；金额、利率、总期限上限必须配置并标记当前规则版本，不能把页面一亿元/100%的技术试算上限直接当作正式业务限额。

serviceFeePolicy区分UNCONFIGURED、DISABLED、ENABLED。未配置不能展示“免费”，也不能凭主表service_fee默认0认定免收费。正式签署开关应要求已明确关闭收费或收费能力已就绪；开启收费还必须具备服务费订单/支付设计。

### 5.2 通用条件请求

创建、编辑和试算共用条件DTO；试算允许不传creatorRole、用途及备注，保存要求完整业务信息。

```json
{
  "creatorRole": "lender",
  "principalAmount": "10000.00",
  "loanDate": "2026-10-11",
  "purpose": "日常周转",
  "remark": "",
  "repaymentMethod": "annuity",
  "interestFree": false,
  "annualRate": "0.06000000",
  "installmentCount": 12,
  "repaymentCycleMonths": 1,
  "firstDueDate": "2026-11-11",
  "prepaymentRule": "actual",
  "overdueTerms": "不额外收取逾期费用"
}
```

| 字段 | 校验/存储 |
| --- | --- |
| creatorRole | borrower/lender映射主表1/2；不能传creatorUserId。 |
| principalAmount | 大于0，最多两位小数，在服务端配置限额内。 |
| loanDate | 合法日期；允许记录已发生借款的日期，但是否受理及跨度由配置决定，不声称已经确认资金交付。 |
| repaymentMethod | once/annuity/principal/interest/flat/custom。loanType由服务端推导。 |
| interestFree | true时利息为0，annualRate须为0或省略、fixedInterestAmount须为0或省略；矛盾字段拒绝。 |
| annualRate | 比例值最多八位小数；实际范围受配置约束。flat有息时不以它计算利息。 |
| fixedInterestAmount | flat有息时必填，非负金额；总利息输入必须独立保存，不能反推成年利率。 |
| dueDate | once必填；其他方式最终日期由计划生成，客户端不提交。 |
| installmentCount / repaymentCycleMonths / firstDueDate | 标准分期必填；once和custom不用这套生成字段。 |
| customPlan | custom必填，2至60行，每行只有dueDate/principalAmount；本金非负、合计等于主本金、日期严格递增。 |
| purpose / remark / overdueTerms | 长度分别255/500/1000，纯文本；渲染转义，不接受任意HTML。 |
| prepaymentRule | 沿用页面actual/agreement，合同须使用对应模板解释；只记录约定，不实现提前结清重算。 |

custom示例：`[{"dueDate":"2026-11-11","principalAmount":"3000.00"},{"dueDate":"2026-12-11","principalAmount":"7000.00"}]`。每期利息、合计、余额不接受客户端提交。不适用的非空字段明确报错，避免静默丢弃利息约定。

### 5.3 POST /notes/quote

登录及实名校验后试算；不写主表、计划、合同或签署记录。返回规范化conditions、calculationVersion、interestRule、summary、完整plan和warnings。

summary含principalAmount、interestAmount、totalAmount、dueDate、firstAmount、lastAmount、maximumAmount。plan每行含periodNo、dueDate、principalAmount、interestAmount、totalAmount、remainingPrincipal。金额都为字符串。

### 5.4 六种方式的计算规则

| 方法 | 服务端规则 |
| --- | --- |
| once | 一期本金全还，利息=本金×年利率×实际天数/365。 |
| principal | 本金按分平均分配，末期补齐；利息基于本期开始前剩余本金。 |
| annuity | 按实际各期利率的折现因子求共同支付额；逐期拆分本息，末期清偿剩余本金并处理尾差。 |
| interest | 各期按实际天数/365支付利息，最后一期还全部本金。 |
| flat | 主本金和约定总利息分别分配；不得描述为按剩余本金计息。 |
| custom | 使用约定日期和本金，本期利息=期初剩余本金×年利率×实际天数/365。 |

annuity/principal正常周期使用年利率×周期月数/12；首期不等于借款日加一个周期时，首期用实际天数/365，后续仍用周期利率。其他按天方式即使跨闰年也沿用固定365分母，展示并写入条款。

计息天数取日期差，包含起日、不含止日。完整周期按借款日锚点生成；自定义首期按首期日锚点生成后续日期。1月31日→2月末→3月31日，不能漂移到3月28日。

服务端采用BigDecimal高精度中间计算，金额最终ROUND_HALF_UP到分；等额本息中间折现精度及舍入顺序固化到calculationVersion，不使用double作为正式算法。本金均分采用向下取整到分、末期补齐；固定利息按分分配，末期调整且任何期不得为负。尾差不允许造成负本金、负利息或本金溢出。

最终必须满足Σ本金=主本金、Σ利息=总利息、每期本金+利息=本息、Σ本息=主总额、最后余额=0。无息annuity/principal/flat统一规范化为principal，interest仍保留末期还本语义，custom保留自定义本金分配。

服务端结果是正式来源；H5旧试算仅作输入反馈，进入计划/签署预览必须使用服务端结果。不能要求后端以旧JavaScript浮点等额本息算法为准。

## 6. 草稿接口

### 6.1 POST /notes

请求为完整条件DTO及Idempotency-Key。从登录用户取本人实名快照，对方姓名/HMAC/密文全部NULL，status=0、两方签署状态=0；生成noteNo。

事务内完成条件校验、计算、主表插入和所有计划插入；任一步失败整体回滚。返回201及`{ id, noteNo, status, stage, version, conditions, summary, plan, actions }`。同一幂等请求返回原借条，不重复创建。

“草稿”指尚未签署的完整借条草案，本期不支持缺本金、缺日期的半成品自动保存；现有页面未填完时继续保持内存表单。如后续需要跨设备恢复半成品，须另设计存储，不往当前NOT NULL字段写占位值。

### 6.2 PUT /notes/{id}

请求`{ version, conditions }`。只允许本人创建、未锁定、双方均未发起/成功签署的草稿。creatorRole可以在未锁定阶段切换；切换时清空原侧身份并从本人核验资料重新构建，始终保证另一方空。

事务内锁行或按version条件更新，重算主表合计，删除旧计划、写入完整新计划，version+1。返回与创建一致的草稿DTO。编辑成功使旧预览摘要失效。

### 6.3 DELETE /notes/{id}

version为必填查询参数。仅本人未锁定草稿允许物理删除，事务内先删计划再删主表；解决现有计划外键限制。返回204。签署开始后的记录改走cancel，不物理删除。

删除与编辑、签署互斥；已删除的重复请求返回204，但不能用该行为泄露别人的借条是否存在。

## 7. 预览与签署

### 7.1 GET /notes/{id}/preview

发起人或已绑定当事人可见；未绑定候选人须通过分享接口授权。返回`{ noteId, version, previewHash, termsHash, templateVersion, calculationVersion, parties, conditions, summary, plan, clauses, actions }`。

发起人预览中另一方为null/待对方加入。开始签署时生成规范化、可复现的terms_snapshot，固化条件、全部计划、计息规则、模板、本人身份快照及“另一方以后由实名签署者加入”的机制，计算terms_hash并锁定。

对方预览返回原锁定条款及本人拟加入信息，同时生成该用户专属previewHash，将原termsHash、本人核验身份版本及加入角色纳入摘要。本人身份证仅按必要范围脱敏展示，接口不返回HMAC或密文。

重要依赖：签署服务和合同模板必须支持“发起人先签固定借款条件、对方随后加入”的文件关系，保存发起人原签文件及对方加入后的文件，不能往发起人原签文件中补姓名后声称它仍是原签文件。如果供应商必须双方身份完整才能发起签署，就不能直接接入当前流程；需选支持这种流程的方案或调整合同组织方式，不凭业务代码伪造签名。

### 7.2 POST /notes/{id}/signatures

```json
{
  "version": "3",
  "previewHash": "服务端本次预览返回的摘要",
  "confirmed": true,
  "shareReference": "仅未绑定对方提交"
}
```

Idempotency-Key必填。signatureRole不由客户端指定，服务端依据发起人身份/缺失一方推导。confirmed表示用户明确核对，不代表已经签署成功。

返回202：`{ noteId, requestId, signatureRole, signStatus, stage, version, nextAction }`。nextAction由实际服务商决定，可为`{ type: "REDIRECT", url: "…" }`或待查，不接受客户端任意returnUrl；签署跳转URL不可写日志或当作正式协议下载地址。

发起人操作：核对version和previewHash，固定快照/termsHash/模板/计算版本，记录锁定时间、本方sign_status=1、请求ID；提交事务后调用供应商，不持有数据库行锁等待HTTP。请求ID必须在外部调用前落库，并作为供应商幂等业务号，以覆盖“本地提交成功但外部调用超时”。

对方操作：校验分享reference、主状态7、发起人已签、本人实名、与发起人不是同一身份证HMAC、另一方未绑定。将候选人身份快照和本次签署请求上下文持久化，设置缺失侧sign_status=1。此时正式对方姓名/HMAC/密文仍NULL；不是已加入。

多人争抢时仅一人能启动当前签署会话，其他返回409 SIGNING_IN_PROGRESS。成功后其他返回NOTE_ALREADY_SIGNED。失败且供应商确认会话终止后释放处理中位置，其他用户仍可签；没有“指定邀请人”的业务限制。

失败重试保持锁定原条款，不允许编辑后复用旧签署。需要改条款时取消并重新创建。相同幂等键返回原会话；明确失败后重试必须使用新key和新requestId。

### 7.3 GET /notes/{id}/signatures/current

只有发起人、正式当事人和当前会话候选人有权查询；候选人需同时提供shareReference。返回本人的requestId/signStatus、整体stage/status/version、failureCode/retryable/nextAction，不返回其他候选人的个人信息。

前端在签署跳转返回后轮询该接口，而不是靠跳转参数将页面改为成功。可先每2秒查询，超过30秒降低频率，离开页面停止轮询；最终由后台回调/主动查询推进。

### 7.4 供应商回调

`POST /api/iou/signing/{provider}/callback`不使用用户登录鉴权，使用服务商要求的验签、时间戳及防重放机制。响应按该供应商协议返回。

回调必须校验requestId、供应商业务号、文档/条款摘要、实际签署人实名标识和终态。身份不一致不能写入成功。只有可信回调或服务端主动查询可以改为成功；不提供用户POST“签署成功”接口。

事务内锁主表，核对当前requestId和候选人快照。已经处理的同一成功回调直接应答；旧请求、其他签署人、与取消相冲突的回调不能覆盖新会话或身份。处理结果保留关联凭证便于排查。

发起人成功：写本方signed_at、sign_status=2、凭证/原签文件/hash、status=7。对方成功：根据持久化候选人快照一次性补齐缺失方身份、signed_at、sign_status=2及凭证；正式绑定和成功状态必须同一事务提交。

文件生成可能异步，双方成功后先保持status=7、stage=FINALIZING。服务端取得最终文件并校验hash、签署证据后保存agreement_file/hash；满足收费条件后才设置status=2/effective_at，或转6待收费。最终文件失败只重试生成，不重复签署，也不允许另一人再签。

后台补偿任务查询sign_status=1或FINALIZING记录，通过requestId向供应商核对；覆盖回调丢失、调用超时、进程重启。不能因前端超时、Redis锁过期或回调暂时未到就释放候选人。只有供应商确认终止/失败后才能释放。

## 8. 分享、接受与取消

### 8.1 GET /notes/{id}/share

只允许发起人查看自己已签、尚待对方签且未取消的借条，返回`{ shareUrl, reference, status, stage, canSign }`。正在签署时可以显示已有链接，但canSign=false；链接访问会显示签署处理中。

分享reference建议用服务端签名的不可篡改公开定位串，携带noteId和域标识，不含身份证/姓名，不设置业务到期时间，不建邀请表，不保存每次分享次数。它用于识别持有链接的访问，并非指定接受者或二次邀请确认。签名密钥由配置管理，不硬编码；密钥轮换兼容已发链接。

不直接用自增id拼公开详情URL，防止枚举访问。任何人获得reference后仍可作为对方进入流程，符合开放链接要求。

### 8.2 GET /shared-notes/{reference}

匿名访问401，H5登录后回到原分享路由。登录未实名返回403并引导现有核验流程。reference校验成功且借条待签时，返回锁定原条款、发起人显示姓名、本人拟加入角色/姓名、脱敏身份、summary、plan、previewHash、version和actions。

该响应是预览，不写正式对方字段，不向我的列表添加借条、不增加“待我确认”数量。返回当前候选人的信息仅从本人会话读取。

若访问者为发起人，返回只读查看动作，不允许签另一方；已签对方返回本人详情入口。已取消或已被其他人签署，非当事人只看到不可签结果，不展示完整已完成合同及其他签署者身份。

### 8.3 POST /notes/{id}/cancel

请求`{ version, reason }`，reason最多255字符。发起人可以取消草稿、已确认失败的签署记录和当前无人签署中的status7借条；签署处理中返回409 SIGNING_IN_PROGRESS，提示等待真实结果或由供应商取消能力完成终止。

本期不支持取消签署中的会话以简化外部竞争；未来若接入该能力，必须供应商确认终止后再改主状态。双方均签署成功、FINALIZING、status2/6均不能使用此接口。重复取消返回当前取消结果。

取消后保存原签文件/证据及条款，分享链接再次打开显示已取消。不做解绑再复用，也不静默删除历史签署文件。

不存在“对方拒绝整张借条”接口。用户不接受时离开即可，不能让任意链接访问者终止发起人的借条。重新发起可由前端复制条件调用POST /notes，服务端重新算并生成新编号，不复用身份、签名、文件或费用结果。

## 9. 列表、详情、计划和文件

### 9.1 已有查询接口扩展

- `GET /summary`维持生效借条本金统计，不将计划remainingPrincipal当实际余额；pendingCount继续表示已绑定历史待确认，不计算未知开放链接。
- 可增加initiatedWaitingCount/signingCount等独立待办字段，不能改变pendingCount含义误把本人发起借条算成待本人签。
- `GET /notes`保留role=all/borrower/lender、status=0..7、pending、page/size；size上限50，排序createTime/id倒序。
- 列表增加creatorRole、stage、mySignStatus、counterpartySignStatus、actions。待加入姓名保留现有展示兼容。
- `GET /notes/{id}`增加规范化conditions、version、签署展示状态、条款摘要、模板版本和计划汇总，不返回实体内部字段集合。
- 历史记录repaymentMethod/creatorRole为空时标明legacy=true，不伪造计划、签署凭证；新签署接口拒绝直接推进历史流程。

### 9.2 GET /notes/{id}/plan

正常详情权限，返回`{ calculationVersion, interestRule, summary, content: [完整计划] }`。最多60期，可一次返回；分享页复用同一计划投影。remainingPrincipal明确为计划余额，不能标注“实际欠款”。

### 9.3 GET /notes/{id}/agreement

只给正式当事人访问；候选人正式绑定前不能下载双方最终协议。query disposition=inline/download。未生成返回409 AGREEMENT_NOT_READY。

文件存于私有存储，接口鉴权后流式输出PDF，或返回短时文件访问URL；短时文件URL有效期与永久分享链接是两回事。不能直接返回agreement_file内部路径，也不能用公开对象存储地址绕过当事人权限。

发起人原签文件与最终文件分别保留，最终协议hash对应实际文件。签署凭证不通过普通详情公开；管理端查看需要单独权限和审计。

## 10. 事务、幂等及数据库补充

已有主表+计划表足够承载业务，不需要新增邀请表、签署表、双方用户ID或条款版本表。但详细接口设计暴露出以下主表补充需求，本方案尚未执行迁移：

| 建议字段 | 理由 |
| --- | --- |
| fixed_interest_amount decimal(18,2) NULL | 固定总利息是表单条件，需要草稿恢复和重算；不能只保留计算结果而丢失输入语义。 |
| create_request_key varchar(64) ASCII NULL | 创建请求幂等，增加UNIQUE(creator_user_id, create_request_key)，历史为NULL。 |
| create_request_hash char(64) ASCII NULL | 校验同一创建key的内容一致，编辑后仍保留原创建请求摘要。 |
| active_sign_context longtext NULL | 存当前签署请求摘要/幂等key、候选人实名密文快照、身份HMAC、供应商会话标识、模板/文件摘要、会话阶段及失败终止结果；普通接口不可读写。 |

active_sign_context不能存身份证明文。它记录“签署候选人”，不等于正式borrower/lender字段；正式字段只在签署成功时写入。重启后不能依赖浏览器或内存确定谁签的，Redis可辅助限流但不是唯一事实来源。

同一侧当前请求仍使用已有sign_request_id唯一关联。旧会话的证据保留在签署服务商/私有凭证存储中；旧回调只识别为已失效请求，不覆盖当前上下文。若选用服务商不能提供持久化历史会话及可检索幂等结果，则须重新评估记录方案，不能声称单个上下文覆盖就能保留全部尝试历史。

关键条件更新示意：对方发起要求status=7、缺失方identity IS NULL、缺失侧sign_status不为1/2、version匹配；对方成功要求requestId匹配且缺失方仍空。后台CRUD沿用禁止修改签署锁定记录的保护，用户写服务独立实现状态机，不能绕过它直接setStatus。

外部供应商操作采用“本地持久化请求→提交事务→调用供应商→回调/主动查证→条件事务更新”，不把HTTP置于长数据库事务内。供应商必须支持按业务requestId幂等调用/查询；后台补偿恢复未提交或未知结果请求。

创建幂等键记录保留在主表；草稿删除后同一key是否再受理的语义为：删除结束该草稿生命周期，前端下一次创建必须生成新key。签署幂等以当前请求+供应商历史查询判断，旧成功请求不能因上下文更换而再次创建签名。

费用和合同模板配置在开始签署时固化，不允许中途改变已签条款或收费约定。具体收费快照结构放入terms_snapshot，不把运营当前费率当作已签借条费率。

## 11. 错误码与前端处理

| code | HTTP | 前端处理 |
| --- | --- | --- |
| IDENTITY_NOT_VERIFIED | 403 | 引导实名核验。 |
| NOTE_NOT_FOUND | 404 | 不存在或无权查看统一提示。 |
| INVALID_CONDITIONS / INVALID_PLAN | 400 | 展示字段/期次错误，保留填写内容。 |
| CONFIG_NOT_READY | 503 | 显示暂未开放，不能生成虚假签署结果。 |
| VERSION_CONFLICT / PREVIEW_CHANGED | 409 | 刷新详情并重新核对，禁止静默自动确认。 |
| TERMS_LOCKED | 409 | 引导取消并重新发起。 |
| SELF_SIGN_NOT_ALLOWED | 403 | 显示本人不能作为另一方签署。 |
| SIGNING_IN_PROGRESS | 409 | 提示已有签署会话，当前本人可恢复自己的会话。 |
| NOTE_ALREADY_SIGNED / NOTE_CANCELLED | 409 | 分享页显示已完成或已取消，关闭签署按钮。 |
| IDEMPOTENCY_CONFLICT | 409 | 同一操作key内容发生变化，要求刷新或开始新的明确操作。 |
| SIGN_PROVIDER_UNAVAILABLE | 503 | 提示结果待查/可重试，由retryable决定，不假定失败。 |
| AGREEMENT_NOT_READY | 409 | 展示正在生成最终文件。 |

接口返回actions、stage、retryable是前端依据；服务端仍需独立校验所有动作，不依赖按钮是否禁用。

## 12. 页面联调路径

| 页面/动作 | 调用顺序 |
| --- | --- |
| 进入发起页 | GET me + GET note-options。 |
| 填写完成进入计划 | POST notes/quote；显示服务端计算结果。 |
| 进入借条预览 | 首次POST notes，之后PUT notes/{id}；GET preview；核对勾选。 |
| 签署并邀请对方 | POST signatures；完成服务商签署后GET signatures/current；确认发起人成功后GET share。 |
| 对方打开链接 | 登录返回原路由；GET shared-notes/{reference}；展示本人拟加入身份和原条款。 |
| 对方确认签署 | POST signatures附shareReference；轮询本人结果；正式绑定后转正常详情。 |
| 最终查看 | GET notes/{id} + GET plan；文件就绪后GET agreement。 |
| 返回修改 | 未锁定时编辑并PUT；锁定后取消/复制重新发起。 |

签署开关关闭时页面仍可试算/保存草稿，明确显示未开放。不能仅凭勾选或请求202就跳转“借条已生效”。

## 13. 开发拆分与验收

### 第一批：规则、试算与完整草稿

note-options、quote、POST/PUT/DELETE notes、详情条件和plan。后端计算与事务完成后接入H5前两步及预览草稿保存。无外部签署依赖，可以先落地。

验收：六种方式、无息、非整首期、闰年/月末、季度、小额利息尾差；本金/利息/本息不变量；本人身份读取、另一方NULL、半套身份拒绝；创建重复提交唯一；编辑版本冲突；主表计划回滚；草稿删除完整清理。

### 第二批：合同预览、发起人签署与分享

确定支持当前文件关系的签署方式/供应商及正式模板，补主表所需字段，完成preview、signature请求/查询、回调、后台补偿、share及cancel。

验收：原签文件不可变；预览摘要变化拒签；接口不能客户端伪造状态/签署人；外部超时可恢复；回调重放/伪造/旧请求不误推进；锁定后编辑和后台修改拒绝；分享链接不设业务到期时间。

### 第三批：对方加入与最终借条

完成shared-notes、候选人上下文、并发唯一签署、成功绑定、最终文件核验及生效状态；接入对方页面和双方详情。

验收：打开不绑定；本人不能签另一侧；多人发起仅一个会话、仅一个正式对方；签署失败终止后其他人可签；旧候选人迟到回调不覆盖新候选人；签署处理中取消拒绝；最终文件生成失败可重试但不重复签；非当事人不能下载已完成协议。

### 第四批：收费（仅明确启用时）

当前服务费没有订单/支付能力，不应只补一个“已支付”接口。若启用，另行设计服务费订单及退款/回调存储，接口预计为POST notes/{id}/fee-orders、GET fee-orders/{orderNo}、POST fee-orders/{orderNo}/payment、供应商payment callback；借款人支付，服务端计费，可信支付结果后6→2。

本方案不要求现在新增费用表。若明确关闭收费，第三批直接完成0→7→2；若收费仍未配置，签署能力保持关闭。

### 本期不开放

实际资金放款、每期还款登记/确认、部分还款冲抵、实际余额、提前结清、展期、逾期费用计算、签署后修改/解除、自动结清。这些业务不能仅更新计划表或主状态，需要各自的交易与证据设计。

## 14. 代码组织建议

eladmin-system负责登录身份解析、H5控制器及供应商回调入口；eladmin-iou负责计算、草稿事务、签署状态机、计划和文件服务。以业务DTO返回结果，不直接序列化IouNote实体。

建议拆为IouNoteOptionsService、IouRepaymentCalculator、IouNoteDraftService、IouNotePreviewService、IouNoteSigningService、IouNoteShareService、IouAgreementService和SigningProviderAdapter；复用现有IouAppQueryService并扩展投影。

分享HMAC与身份证HMAC使用不同用途的密钥/域，避免混用。签署平台凭据和文件存储凭据通过环境配置，测试使用合成身份和供应商桩；最终上线前必须验证真实供应商的证据、文件关系及补偿能力。
