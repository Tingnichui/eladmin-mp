# 电子借条后台初始化

本轮按《代码生成流程》初始化独立模块 `eladmin-iou`，数据源为 `master`，数据库为 `eladmin`。
两张业务表为 `iou_user`、`iou_note`；通过运行中的代码生成器同步、配置、保存并生成。

## 模块与菜单

- 后端包：`me.zhengjie.iou`，父 POM 和 `eladmin-system` 已加入模块及依赖。
- 一级目录：电子借条，路径 `iou`。
- 借条用户管理：组件 `iou/iouUser/index`，管理接口 `/api/iouUser`，权限 `iouUser:list/add/edit/del`。原系统已有“用户管理”，菜单标题须全局唯一。
- 借条管理：组件 `iou/iouNote/index`，管理接口 `/api/iouNote`，权限 `iouNote:list/add/edit/del`。
- `sql/iou_menu.sql` 为超级管理员角色追加菜单及按钮权限，不替换已有授权。
- H5 用户端接口和登录体系不在本轮实现范围内，不能直接复用上述管理员接口。

## 初始化脚本与生成配置

1. `sql/iou_user.sql`、`sql/iou_note.sql`：业务表。
2. `sql/iou_user_id_no_hash.sql`、`sql/iou_note_pending_service_fee.sql`：旧结构升级脚本。
3. `sql/iou_dict.sql`：认证状态、借款类型、借条状态字典。
4. 在代码生成器选择 master，同步两张表字段。
5. `sql/iou_generator_fields.sql`：字段展示、必填、查询和字典配置，可重复执行。
6. 生成配置：模块 `eladmin-iou`，包名 `me.zhengjie.iou`，不去表前缀，不覆盖。
7. 页面路径分别为 `eladmin-web/src/views/iou/iouUser` 和 `eladmin-web/src/views/iou/iouNote` 的工作区绝对路径。
8. 先保存底部生成配置，重新读取确认，再保存字段并生成。
9. 编译并通过 `scripts/start-dev.ps1 -RestartBackend` 加载代码后执行菜单脚本。

## 必要的生成后调整

- 密码、身份证明文输入只用于提交，不回显；数据库密文和 HMAC 字段不接收客户端直接赋值。
- 密码经 BCrypt 存储；编辑留空保留原密码。
- 身份证统一去首尾空白并转大写，后台计算 HMAC-SHA256 及加密密文，用户和借条使用相同规则。
- 密码和证件的明文、密文、关联值均排除在列表响应、审计参数、toString 和导出之外。
- 身份证编辑留空保留旧值；手机号、姓名或证件变化会重置用户认证状态。
- 校验发起人存在、双方证件不同、金额与日期基本一致性。
- 创建及更新时间由数据库维护，普通表单不修改签署、生效时间。
- bigint 标识保持字符串序列化，前端发起人 ID 用文本框，避免数字精度丢失。

这只是后台基础 CRUD。后台录入证件或维护认证状态不等于已调用真实三要素服务。
借条金额仍由后台填写；计息、签约、支付和业务状态机未实现。

## 本地敏感配置

`JASYPT_ENCRYPTOR_PASSWORD` 用于身份证密文加密。
另使用独立的 `IOU_IDENTITY_HMAC_KEY`，只存放于已被 Git 忽略的 `.codex-local/env.ps1`，启动脚本自动加载。
文档、源码和 SQL 不保存密钥值。部署新环境时通过环境变量配置同一 HMAC 密钥，
否则既有用户与借条的身份证关联值无法匹配。密钥轮换需要专门迁移，不能直接替换。

## 验证命令

```powershell
# 后端敏感字段与身份关联测试（从 eladmin 目录执行）
mvn -pl eladmin-iou -am -DskipTests=false -Dtest=IouSensitiveDataTest,IouPermissionTest -Dsurefire.failIfNoSpecifiedTests=false test

# 管理端统一使用项目脚本选择 Node 16/14
./scripts/run-frontend.ps1 -NpmArguments @('run', 'lint')
./scripts/run-frontend.ps1 -NpmArguments @('run', 'build:prod')
```

生成后的文件包含密码处理和敏感字段保护，后续不要直接覆盖生成；需要重新生成时先对比调整。
完整 CRUD 验收只创建可识别的合成测试记录，完成后按测试记录精确清理，不删除真实业务数据。

## 本轮验收记录

- 通过现有已登录的本地管理端会话操作生成器，分别保存并复查生成配置。
- 后端 clean install 构建及重启成功，管理端 lint 和生产构建成功。
- 用户及借条页面：列表、查询、新增、修改、导出、删除通过；用户列表使用11条合成记录验证跨页分页和默认降序。
- 两份导出文件为有效 XLSX，字典值导出为中文，密码和证件相关字段不出现在文件中。
- 实际数据库检查确认 BCrypt、身份证密文及HMAC保存正确，借条双方HMAC匹配用户表，编辑更新时间由数据库刷新。
- 无权限角色方法拦截、仅查询权限不允许写入，以及敏感字段和超大编号测试通过；匿名访问两组管理接口返回401。
- 审计参数未保存测试密码或身份证明文。
- 合成测试记录已清理，两张业务表恢复为空表；菜单和字典保留。
