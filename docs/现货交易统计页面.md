# 现货交易统计页面

本文档记录交易统计页面的当前范围、持仓分布图口径、汇总信息和布局约定。页面当前只展示普通现货；U 本位合约、币本位合约及对冲统计暂不纳入页面。

## 1. 页面目标

页面优先回答以下问题：

- 当前每笔未平仓买入发生在什么时间、什么价格。
- 每笔买入在当前价格下是盈利还是亏损。
- 当前价格、持仓均价和买入点之间的位置关系。
- 账户与现货交易的关键汇总数据。

账户选择、交易对选择、查询、同步数据、现货下单和当前挂单入口继续保留。底仓设置、调整和解除统一通过图表下钻抽屉操作；全局底仓记录仍由左侧“现货底仓”页面管理，交易统计页不再提供重复的底仓管理弹窗。

## 2. 页面布局

页面从上到下分为两块：

1. 筛选工具栏：账户、交易对、查询、同步数据、现货下单和当前挂单；右侧通过“账户资产”入口悬浮查看账户统计，通过“全部汇总”入口悬浮查看交易统计。
2. 持仓买入分布：不显示重复的页面内标题，直接展示核心指标、图表模式和盈亏筛选；点击买入点或价格区间后在抽屉中查看明细。

桌面端采用视口高度内的弹性布局：筛选栏保持稳定高度，持仓图表占用全部剩余空间，尽量避免整页滚动。账户统计和低频交易汇总不再占用底部固定区域，统一使用带打开、关闭延迟的悬浮弹层，关闭后不占页面高度。窗口宽度小于 `1200px` 或高度小于 `760px` 时恢复自然高度和页面滚动，避免内容被裁切。

## 3. 逐笔买入分布

页面保留“逐笔买入”模式：

- 横轴：真实买入成交时间 `openTime`。
- 纵轴：买入价格 `openPrice`。
- 气泡大小：该买入批次当前剩余数量 `qty`。
- 绿色：当前净盈亏大于等于零。
- 红色：当前净盈亏小于零。
- 蓝色虚线：当前现货价格。
- 橙色虚线：当前持仓均价。

悬浮提示展示买入时间、买入价格、剩余数量、盈亏平衡价、当前盈亏和收益率。点击买入点可以打开该批次的持仓与底仓操作抽屉。

`tradeList` 中的每条数据必须对应一个未平仓买入批次。后端不能按买入价格预先合并，否则会丢失真实成交时间，也无法区分同价位的多笔买入。前端允许兼容读取 `tradeTime`，但不会在时间缺失或无效时使用当前时间伪造买入时间；无有效时间的点不进入时间轴。

## 4. 价格区间聚合

默认使用“价格区间聚合”模式，前端按可调价格间隔将逐笔持仓分组。默认间隔为 `2500 USDT`，通过左右按钮在 `500`、`1000`、`2500`、`5000 USDT` 四个固定档位之间切换。

每个区间展示：

- 持仓总数量。
- 成交笔数。
- 加权买入均价。
- 底仓笔数、底仓数量和可撮合数量。
- 当前盈亏和收益率。

盈利区间、亏损区间和持仓均价所在区间使用不同颜色，当前价格所在区间使用蓝色边框和蓝色刻度文字强调，不再额外绘制重复的“当前价格”文字标签。该模式只改变展示方式，不改变后端逐笔持仓数据和 FIFO 撮合结果。

含底仓的价格区间使用蓝色锁定标识。点击区间柱后打开该区间的逐笔买入列表，列表展示买入时间、成交 ID、买入价格与金额、持仓及可撮合数量、净盈亏、收益率、盈亏平衡价和底仓信息。用户可以对具体买入批次设置、调整或解除底仓，也可以在区间摘要栏批量设置或解除。逐笔买入模式中，含底仓的买入点使用蓝色描边和锁标识，点击后可直接进入该批次的持仓与底仓操作抽屉。

区间持仓抽屉默认按币安订单 ID 聚合展示，同一订单产生的多个成交 ID 合并为一个可展开的订单行。订单行汇总加权买入均价、持仓数量、可撮合数量、当前盈亏和底仓状态；展开后仍按成交 ID 展示并执行底仓操作。顶部同时区分订单数、成交笔数和底仓成交笔数，并允许切换到“按成交”视图。统计接口必须为每个未平仓买入批次返回 `orderId`；历史记录缺少订单 ID 时，以成交 ID 独立成组。该聚合只影响展示，不改变逐笔 FIFO、底仓记录或批量接口的成交 ID 口径。

在底仓操作抽屉内设置、调整或解除后，页面只就地更新当前行和区间汇总，不立即关闭抽屉或重新查询统计。用户关闭抽屉后，再统一刷新图表和页面统计。

价格区间存在未设置底仓的买入批次时，可在抽屉摘要栏使用“一键设置底仓”，将这些批次当前的全部剩余数量设置为底仓；已有底仓的批次保持不变。价格区间存在底仓时，也可使用“一键解除”批量解除该区间的全部底仓。两种批量操作都由后端事务处理，成功后只更新抽屉内容，关闭抽屉时再统一刷新统计。

持仓图表提供独立的底仓筛选：“底仓不限”“含底仓”“不含底仓”。该筛选可与“全部成交”“盈利成交”“亏损成交”组合使用。逐笔模式直接筛选买入成交批次；价格区间模式先筛选成交批次，再按价格区间重新聚合数量、笔数和盈亏。只要成交批次的有效底仓数量大于零，即归入“含底仓”；否则归入“不含底仓”。

批量设置调用 `POST /api/binanceSpotCorePosition/batch-lock`，请求体包含账户、交易对和成交 ID 数组，并沿用 `binanceSpotCorePosition:add` 权限。后端以事务内最新的剩余数量作为底仓数量，对重复成交 ID 去重并跳过已有底仓。批量解除调用 `PUT /api/binanceSpotCorePosition/batch-release`，请求体为底仓记录 ID 数组，并沿用 `binanceSpotCorePosition:edit` 权限。任意记录校验或操作失败时，整批事务回滚，避免区间出现只处理一部分的状态。

## 5. 现货限价止盈止损下单

筛选工具栏的“现货下单”按钮用于提交普通现货条件限价单，支持买入和卖出。下单接口为：

```text
POST /api/binanceTradeInfo/spot/order
```

接口沿用 `binanceTradeInfo:createPos` 权限，请求字段包括账户 `uid`、交易对 `symbol`、方向 `side`、订单类型 `type`、数量 `quantity`、触发价 `stopPrice`、委托价模式 `priceMode` 和可选固定委托价 `price`。成功时返回 HTTP 201 和币安 `orderId`。

当前只接受以下订单类型：

- `STOP_LOSS_LIMIT`：限价止损。卖出时通常将触发价设置在当前价格下方，价格跌至止损位后提交限价卖单。
- `TAKE_PROFIT_LIMIT`：限价止盈。卖出时通常将触发价设置在当前价格上方，价格上涨至止盈位后提交限价卖单。

委托价支持两种模式：

- `OPPONENT_FIRST`：页面显示为“对手价1”，后端使用币安 `MARKET_PEG`，不同时发送固定 `price`。
- `FIXED`：触发后使用用户填写的固定委托价，必须传递 `price`。

两种订单都是触发后提交限价单，不保证一定成交。后端校验账户存在、API 有效、交易对属于系统支持的现货交易对，并且不会自动重试真实下单请求，避免网络异常时产生重复订单。

### 5.1 持仓快捷卖出

区间持仓抽屉的订单汇总行和展开后的成交行都提供“卖出”按钮。点击后复用现货下单弹窗，并采用以下默认值：

- 方向固定为 `SELL`，不能在该入口切换为买入。
- 订单类型默认为 `STOP_LOSS_LIMIT`。
- 数量默认为当前行的全部可撮合数量，并限制不能超过该数量。
- 触发价默认填充统计接口返回的当前现货价格，作为编辑起点；实际提交前应按交易计划调整为目标止损位。
- 委托价模式默认为“对手价1”。

可撮合数量为零时禁用卖出按钮；若数量被底仓占用，需要先调整或解除底仓。提交前必须经过二次确认，确认页展示卖出来源、数量、触发价、委托价和卖出后剩余可卖数量。

币安卖单不能指定冲销某一笔历史买入。行内按钮只用于带入所选行的可卖数量并记录操作语境，成交同步后仍按照系统现有 FIFO 规则优先冲销最早的非底仓持仓，不保证最终冲销当前点击的订单或成交。

### 5.2 当前挂单

工具栏的“当前挂单”按钮调用以下接口，按当前账户和交易对实时查询币安，不读取或写入本地委托记录：

```text
GET /api/binanceTradeInfo/spot/open-orders?uid={uid}&symbol={symbol}
```

接口沿用 `binanceTradeInfo:list` 权限，后端固定向币安 `GET /api/v3/openOrders` 传递 `symbol`，避免无交易对查询带来的更高请求权重。列表展示订单号、创建时间、方向、类型、原始数量、已成交数量、触发价、委托价格和状态；币安返回 `pegPriceType=MARKET_PEG` 时显示“对手价1”，有 `peggedPrice` 时同时展示当前锚定价格，不能将普通 `price=0` 误认为真实委托价。

列表只在打开弹窗或点击“刷新”时请求，不自动轮询。当前版本不提供撤单；需要撤单时仍在币安侧操作。

### 5.3 当前边界

当前版本保持轻量实现，尚未建立本地现货委托单中心：

- 下单成功后只展示币安 `orderId`，不在本地保存和持续同步订单状态。
- 页面不扣除尚未触发或尚未成交卖单的占用数量，重复点击可能再次提交真实订单。
- 当前挂单仅实时展示币安仍处于活动状态的订单，不保存状态历史，因此已成交、已取消订单不会留在列表中。
- 暂不提供取消挂单入口，需要在币安侧管理。
- 下单成功后会触发一次现货成交同步；尚未成交的条件单不会改变本地持仓，后续成交仍需再次同步数据后进入 FIFO 撮合。

后续如需扩展，应优先实现本地订单记录、客户端订单号幂等、活动挂单数量占用、订单状态同步和撤单能力，不应只在前端增加状态按钮。

## 6. 指标口径

持仓区域顶部展示当前价格、持仓均价、持仓数量和持仓盈亏。这里展示账户实际剩余现货，包含仍处于锁定状态的底仓；底仓只从 FIFO 撮合候选中排除，不能从持仓图表、数量、成本或浮动盈亏中扣除。收益率不在核心指标区重复展示，仍可通过“全部汇总”查看。交易汇总保留买入总额、卖出总额、收益率、盈亏、手续费、净盈亏、未匹配卖出、持仓总额、持仓盈利和持仓亏损。净盈亏相对上次查询的变化值仅在非零时紧邻主值展示，正负分别使用绿色和红色，悬浮提示说明比较口径；零值或无上次数据时不显示。

图表优先使用接口返回的 `netPnl`、`roi` 和 `breakEvenPrice`。字段缺失时，前端使用当前价格、买入价格、剩余数量和手续费率进行展示层计算；该计算不写回数据库，也不替代后端统计口径。

## 7. 查询链路与性能约定

`GET /api/binanceTradeInfo/stats` 是当前页面的现货专用统计接口。接口只返回页面需要的 `spotFuturesStatsInfo`、`accountInfo`、`realtimeStatus` 和 `warnings`，不在该链路中计算 U 本位合约、币本位合约、资金费或现货对冲统计，也不应为对冲统计加载全部历史现货成交。

现货价格和账户统计并行读取，具有以下约定：

- 实时快照的新鲜期为 10 秒，连续查询优先返回 Redis 缓存。
- 同一账户和交易对的并发请求应合并，避免重复请求币安。
- 实时请求共享 3 秒截止时间；超时或失败时优先使用 10 分钟内的旧快照并返回告警。
- 账户统计的 C2C 历史汇总使用 `BINANCE:USTSTATS:<uid>` 长期缓存；普通“查询”不重新拉取 C2C 历史，点击“同步数据”时才重新计算并覆盖缓存。

现货本地统计保留三类数据库读取：已实现成交汇总、未匹配卖出数量和未平仓买入明细。未匹配卖出直接汇总状态表的 `remaining_qty`；未平仓明细必须返回给图表，不得为减少 SQL 而丢失逐笔数据。当数据量显著增长且执行计划证明有需要时，再考虑合并前两个汇总查询或维护预聚合结果。

开发和生产环境都不应使用 `StdOutImpl` 逐行输出 SQL 结果集；如需调试 SQL，通过 SLF4J 日志级别临时开启。
