# 现货交易统计页面

本文档记录交易统计页面的当前范围、持仓分布图口径、汇总信息和布局约定。页面当前只展示普通现货；U 本位合约、币本位合约及对冲统计暂不纳入页面。

## 1. 页面目标

页面优先回答以下问题：

- 当前每笔未平仓买入发生在什么时间、什么价格。
- 每笔买入在当前价格下是盈利还是亏损。
- 当前价格、持仓均价和买入点之间的位置关系。
- 账户与现货交易的关键汇总数据。

原有账户选择、交易对选择、查询、同步数据、底仓管理、持仓明细和持仓订单入口继续保留。

## 2. 页面布局

页面从上到下分为三块：

1. 筛选工具栏：账户、交易对、查询、同步数据和底仓管理。
2. 持仓买入分布：核心指标、图表模式、盈亏筛选和持仓明细入口。
3. 汇总区：左侧账户统计，右侧交易汇总。

桌面端采用视口高度内的弹性布局：筛选栏和汇总区保持稳定高度，持仓图表占用剩余空间，尽量避免整页滚动。底部两张卡片高度一致，交易汇总以两行五列完整展示。窗口宽度小于 `1200px` 或高度小于 `760px` 时恢复自然高度和页面滚动，避免内容被裁切。

## 3. 逐笔买入分布

默认使用“逐笔买入”模式：

- 横轴：真实买入成交时间 `openTime`。
- 纵轴：买入价格 `openPrice`。
- 气泡大小：该买入批次当前剩余数量 `qty`。
- 绿色：当前净盈亏大于等于零。
- 红色：当前净盈亏小于零。
- 蓝色虚线：当前现货价格。
- 橙色虚线：当前持仓均价。

悬浮提示展示买入时间、买入价格、剩余数量、盈亏平衡价、当前盈亏和收益率。点击买入点可以打开持仓明细。

`tradeList` 中的每条数据必须对应一个未平仓买入批次。后端不能按买入价格预先合并，否则会丢失真实成交时间，也无法区分同价位的多笔买入。前端允许兼容读取 `tradeTime`，但不会在时间缺失或无效时使用当前时间伪造买入时间；无有效时间的点不进入时间轴。

## 4. 价格区间聚合

切换到“价格区间聚合”后，前端按可调价格间隔将逐笔持仓分组。默认间隔为 `2500 USDT`，可在 `500—5000 USDT` 之间以 `500 USDT` 为步长调整。

每个区间展示：

- 持仓总数量。
- 买入笔数。
- 加权买入均价。
- 底仓笔数、底仓数量和可撮合数量。
- 当前盈亏和收益率。

盈利区间、亏损区间和持仓均价所在区间使用不同颜色，当前价格所在区间使用蓝色边框强调。该模式只改变展示方式，不改变后端逐笔持仓数据和 FIFO 撮合结果。

含底仓的价格区间使用蓝色锁定标识。点击区间柱后打开该区间的逐笔买入列表，用户只能对具体买入批次设置、调整或解除底仓，不对整个价格区间执行批量锁定。逐笔买入模式中，含底仓的买入点使用蓝色描边和锁标识，点击后可直接进入该批次的底仓操作。

在底仓操作抽屉内设置、调整或解除后，页面只就地更新当前行和区间汇总，不立即关闭抽屉或重新查询统计。用户关闭抽屉后，再统一刷新图表和页面统计。

## 5. 指标口径

持仓区域顶部展示当前价格、持仓均价、持仓数量、持仓盈亏和收益率。这里展示账户实际剩余现货，包含仍处于锁定状态的底仓；底仓只从 FIFO 撮合候选中排除，不能从持仓图表、数量、成本或浮动盈亏中扣除。交易汇总保留买入总额、卖出总额、收益率、盈亏、手续费、净盈亏、未匹配卖出、持仓总额、持仓盈利和持仓亏损。

图表优先使用接口返回的 `netPnl`、`roi` 和 `breakEvenPrice`。字段缺失时，前端使用当前价格、买入价格、剩余数量和手续费率进行展示层计算；该计算不写回数据库，也不替代后端统计口径。

```text
cd eladmin-web
npm run lint
npm run test:unit

cd eladmin
mvn -pl eladmin-invest -am -DskipTests=false test
```
